# Phase 3 验收：产品化（协议协商/权限策略/可观测性）

Phase 3 目标是把系统从“工程可用”推进到“产品可维护”。

## 1. 目标

- 协议版本与能力协商（兼容不同 opencode 版本）。
- 权限策略可管理（撤销 allow_always、按 scope 细分）。
- 可观测性：日志/诊断导出、健康检查标准化。
- VSCodium 打包场景下可运行（不依赖外网/不依赖 VS Code 专有能力作为关键路径）。

## 2. 用例

### TC1：版本不兼容的降级与提示

步骤：
1) 连接到旧版本 opencode server。

期望：
- UI 明确提示“不兼容版本”，并给出升级建议。

### TC2：权限策略管理

步骤：
1) allow_always 授权一次。
2) 在设置中撤销该授权。
3) 再次触发同类操作。

期望：
- 撤销后再次弹窗。

### TC3：诊断导出

步骤：
1) 导出诊断包。

期望：
- 包含：版本号、关键配置（脱敏）、最近 N 条事件、最近 N 条错误。

### TC4：离线/内网环境

步骤：
1) 禁用外网访问。

期望：
- readiness 不依赖 `/app` 这类外网兜底代理。
- 对话与工具仍可用（前提 provider 也可用）。

## 3. 通过标准

- Phase 3 用例全 Pass。
- 任何失败都必须“可诊断”。
